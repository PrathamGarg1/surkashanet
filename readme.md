# SurakshaNet

A Chrome extension that flags abusive Hindi/Hinglish/English content in the
DOM of WhatsApp Web, Twitter/X, and Instagram, runs entirely on-device with
a fine-tuned MiniLM ONNX classifier (~117 MB int8), and logs court-admissible
evidence (SHA-256 hash, timestamp, screenshot, chain of custody) into local
storage.

This repo contains both the extension and the full Modal-based training
pipeline that produces the model the extension ships.

## Running the extension

```bash
npm install
npm run build         # writes dist/
```

In Chrome: `chrome://extensions` → enable Developer Mode → "Load unpacked" → pick
the `dist/` folder. Open WhatsApp Web, Twitter/X, or Instagram and abusive
messages will get an inline severity banner; click the toolbar icon to open
the evidence viewer (export to PDF/JSON, clear, etc.).

The service worker is wired so that **all inference happens locally** —
`env.allowRemoteModels = false` in
[`src/background/service-worker.js`](src/background/service-worker.js) hard-disables any fallback
to the HuggingFace CDN; the only weights it ever loads are
`assets/models/custom-macd-model/model_quantized.onnx`.

## Retraining the model from scratch

The whole pipeline runs on Modal. Each script takes a fresh checkpoint from
the previous one via a shared `surakshanet-artifacts` Modal Volume.

```bash
pip install modal
modal token new                                # one-time

modal run training/modal_train.py              # step 1, ~1–2 h on A10G
modal run training/modal_export.py             # step 2, ~5 min on CPU
modal run training/modal_evaluate.py           # step 3, ~10 min on CPU
```

After step 2, the freshly-quantized artifacts are downloaded straight into
`assets/models/custom-macd-model/`, so re-running `npm run build` rebuilds the
extension against the new model.

### Training data

| Source | Split | Used in |
|---|---|---|
| MACD `hindi_train.csv` (ShareChatAI/MACD) | train | `modal_train.py` |
| MACD `hindi_val.csv` | val (early-stopping, model selection) | `modal_train.py` |
| MACD `hindi_test.csv` | **held out** | `modal_evaluate.py` only |
| Davidson 2017 `labeled_data.csv` | 90% train, 10% **held out** | `modal_train.py` (90%), `modal_evaluate.py` (10%) |

The Davidson 90/10 split is deterministic with `DAVIDSON_SEED = 42` in
[`training/_common.py`](training/_common.py); the held-out row indices are written to
`/vol/davidson_test_indices.json` by step 1 and read back verbatim by step 3
so the two scripts cannot disagree on which rows are held out.

Davidson's 3-way labels are collapsed to the binary scheme matching MACD via
`DAVIDSON_LABEL_MAP` (hate + offensive → abusive, neither → non-abusive).

### Recipe (the "Improved" config)

Defined in `TRAIN_HPARAMS` in [`training/_common.py`](training/_common.py):

- 7 epochs, lr `3e-5`, batch 32, weight decay `0.01`
- cosine LR + 10% warmup
- label smoothing `0.1`
- balanced class weights from train label distribution
- `metric_for_best_model = f1_macro`, `load_best_model_at_end=True`

### No-leakage invariants

1. `modal_train.py` never imports `load_macd_test`. Only `load_macd_train_val`
   and the Davidson 90% slice are seen during training.
2. `modal_evaluate.py` re-derives the train data, hashes every train `text`,
   and asserts that **zero** rows of every test set appear in the train set.
   It aborts with `AssertionError` on any overlap before doing inference.
3. The label convention is fixed in `_common.py` and matches what the
   shipped extension expects: `id2label = {0: "abusive", 1: "non-abusive"}`.

After running all three steps:

| File | Produced by | Contents |
|---|---|---|
| `REPORTS/train_metrics.json` | `modal_train.py` | per-step train loss, per-epoch val metrics, hparams, class weights |

| `REPORTS/eval_metrics.json` | `modal_evaluate.py` | full grid: 3 models × 3 test sets, plus leakage report |
| `REPORTS/confusion_matrices.png` | `modal_evaluate.py` | 3×3 confusion-matrix grid |
| `REPORTS/final_report.md` | `modal_evaluate.py` | human-readable summary, before/after-quantization table, NeurIPS-baseline comparison |
| `assets/models/custom-macd-model/` | `modal_export.py` | the int8 ONNX model + tokenizer the extension loads |

## Where the data goes at runtime

```
WhatsApp/Twitter/Instagram DOM
            │
            ▼
src/content/index.js  ──── chrome.runtime.sendMessage({type: 'ANALYZE_TEXT'}) ───▶  src/background/service-worker.js
            ▲                                                                                  │
            │                                                                                  ▼
src/content/banner.js ◀── sendResponse({isToxic, severity, …}) ──── @xenova/transformers pipeline
                                                                     loads
                                                                     assets/models/custom-macd-model/model_quantized.onnx
                                                                     (env.allowRemoteModels = false)
```

If the verdict is toxic, `src/utils/evidence_logger.js` writes a SHA-256-keyed
incident record to `chrome.storage.local` (both `incident_logs` and
`surakshanet_evidence` keys); the popup at `src/popup/evidence_viewer.html`
reads them back for export.

No request ever leaves the user's browser — both the model and the WASM
runtime ship inside the extension package.
